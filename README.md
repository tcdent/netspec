# netspec

Describe a printed circuit board as Python, and have the description check itself.

A `netspec` design says which parts are on a board and what connects to what. The parts carry the facts from their
datasheets - what each pin *is*, what it may be fed, what it draws. The library compares the two: it checks the
wiring, derives the power tree, works out the layout constraints, breaks the design on purpose to prove its own rules
notice, and writes the result out as a KiCad project - netlist, schematic, and a placed and routed board.

Plain Python 3.12, no dependencies. KiCad is only needed to open what it writes.

Status: 0.8, young. It has carried one real board from idea to fabrication files:
[m2x2_slimsas](https://github.com/tcdent/m2x2_slimsas), a four-layer PCIe Gen4 adapter for two NVMe drives. Expect the API to move.

## A small design

```python
from netspec import *
from netspec.power import Load

# Parts carry the facts, each from its datasheet. A design never repeats them. (Example values, not real parts.)
def barrel_jack(ref):
    p = Part(ref, "5 V input", "EXAMPLE-JACK", source="datasheet, p. 2")
    p.pin(1, "+5V", K.PWR_OUT, volts=V(5), imax=A(2.5), bus=True)    # bus: fed from outside the board
    p.pin(2, "GND", K.GND); return p

def sensor(ref):
    p = Part(ref, "sensor module", "EXAMPLE-SENSOR", source="datasheet r1.4, table 3")
    p.pin(1, "VDD", K.PWR_IN, vmin=V(3.0), vmax=V(5.5)); p.pin(2, "GND", K.GND)
    p.loads["VDD"] = Load(A=mA(205), duty=duty(0.1))           # peak, and the fraction of time it is drawn
    return p

def two_pin(ref, value, mpn, **facts):
    p = Part(ref, str(value), mpn, **facts); p.pin(1, "1", K.PASSIVE); p.pin(2, "2", K.PASSIVE); return p

def build():                                                  # the design: only what connects to what
    c = Circuit("sensor node")
    J, U = c.add(barrel_jack("J1")), c.add(sensor("U1"))
    F = c.add(two_pin("F1", "fuse 500 mA", "EXAMPLE-FUSE", power_pass=True, rating=mA(500)))
    C = c.add(two_pin("C1", uF(10), "EXAMPLE-CAP", farads=uF(10), v_rating=V(10)))
    c.connect("+5V_IN", J["+5V"], F[1])
    c.connect("+5V", F[2], U["VDD"], C[1])
    c.connect("GND", J["GND"], U["GND"], C[2])
    return c

c = build(); r = check(c)                                     # the rules that ship with the library and the parts
for tree in derive(c, r.E, r.W): show(tree)                   # the power tree, derived from the wiring
report(c, r)
mutation_test(build)                                          # break it every known way; every break must be noticed
```

     F1 fuse 500 mA: 5 V  205 mA pk / 20.5 mA avg  peak 205 mA of 500 mA (41%)
        U1 VDD: 5 V  205 mA pk / 20.5 mA avg
== sensor node: 4 parts, 3 nets -> 0 errors, 0 warnings, 0 notes
-- mutation test: 16 mutants generated from the design
  drop_pin          8/8    caught  (must catch)
  short_to_rail     4/4    caught  (must catch)

Nobody wrote a test. Feed the sensor 12 V, leave off the capacitor, undersize the fuse or wire around it, and `check`
says so - and the mutation run is the proof that it would: it made each of those mistakes and confirmed a rule
caught it. A mistake no rule catches is reported as a **rule gap**, a bug in the library, and the run fails.

## The ideas

- **Facts live on parts, topology lives in the design.** A part definition records what each pin is and cites where
  that came from; `verified=True` is set only when a person has checked it against the datasheet, and every run lists
  the parts that are not.
- **Nothing is an arbitrary label.** Net names are for people. Every check runs on pin kinds, electrical
  disciplines, units, ratings and values.
- **Units are types.** `V(3.3)`, `mA(8)`, `k(56.2)`, `uF(47)`. A volt cannot be compared with an amp, and a bare
  number raises.
- **Interfaces connect whole.** A bundle (say, a PCIe x4 link with its sidebands) has a host role and a device role;
  `c.link(a, b)` joins two of them and refuses two of the same role.
- **Emergent testing.** Rules ship with the library and with part definitions. The mutation engine applies every
  wiring mistake it knows to your design and demands that the rules notice.
- **A board is data.** Placement, tracks, vias and pours are Python tuples - often generated by a few lines of
  geometry - and the board file is rebuilt from them, so a change to the spec flows through to copper.

[SPEC.md](SPEC.md) is the full description: concepts and where they come from (Verilog, mostly), every built-in
rule, the mutation operators, the honest list of limits, and the roadmap.

## What is in the box

| Module | What it does |
|---|---|
| `units.py` | Typed quantities with dimension checking. |
| `core.py` | `Part`, `Pin`, `Net`, `Circuit`, bundles, disciplines; the rules that parts attach to themselves (`feedback_divider`, `requires_cap`, `output_filter`, ...); `check` and `report`. |
| `power.py` | `Load`, `Converter`; `derive` walks from each fed net through fuses and converters to the loads - peak and average current, loss, junction temperature, every rating on the way; `stack` budgets several boards on one bus. |
| `mutate.py` | `mutation_test`: generated broken variants of the design, and the verdict on each. |
| `physical.py` | `Fab` (what the board house can do) + the circuit give the layout constraints: rail widths from IPC-2221, differential-pair rules, skew, via limits - as a table and as a KiCad `.kicad_dru` rules file. |
| `layout.py` | Reads a `.kicad_pcb` back and holds it to the spec (independent of KiCad's DRC): is the routed board the specified board? Has its own mutation test, on damaged layouts. |
| `kicad.py` | Writers: netlist, a label-style schematic with its symbol library, the project file (net classes, colours, board rules, library tables), and the board - library footprints placed front or back, tracks, vias, zones, keep-outs, silkscreen. IDs derive from reference designators, so re-exporting updates a layout in place. |

## Using it for a board

`netspec` is not on PyPI; a project depends on it straight from git. In the project's `pyproject.toml`:

    [project]
    dependencies = ["netspec"]

    [tool.uv.sources]
    netspec = { git = "https://github.com/tcdent/netspec" }
    # or, with a checkout beside the project while working on both:
    # netspec = { path = "../netspec", editable = true }

A project is a handful of files:

    <project>/
        pyproject.toml
        parts.py             part definitions, each citing its source
        board.py             the design: parts + connections; runs the checks and the exporters
        placement.py         where things sit            (optional: only if netspec writes the board)
        routing.py           tracks, vias, pours         (likewise)

Run it with [uv](https://docs.astral.sh/uv/): `uv run python board.py`. See
[m2x2_slimsas](https://github.com/tcdent/m2x2_slimsas) for a complete one, including a `Makefile` that goes from
`board.py` to zipped Gerbers.

Board and schematic files are written in KiCad 9 format; `kicad-cli pcb upgrade` and `sch upgrade` bring them to
whatever KiCad you run. They have been exercised against KiCad 10.99 (the development line): KiCad loads them, DRC and
ERC pass on the real board, the schematic and board agree net for net, and `layout.py` reads the saved board back.

## Limits worth knowing before you trust it

A rule is only as right as the part definition under it: type a pin's role wrong and wiring that matches the mistake
passes. The spec checks intent and local rules; it does not simulate - signal integrity, current distribution in
pours, voltage drop and return paths stay with review and measurement. Efficiency and thermal figures are
single-point estimates. The longer list is in [SPEC.md](SPEC.md).
